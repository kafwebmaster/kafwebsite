## 1. 体制と役割分担

| 担当 | 役割 |
|---|---|
| **Claude Code** | コード実装全般(Astro 構築、全ページ移植、CMS 連携、アーカイブ機能、データ移行、ドキュメント作成)、新規ページ・コンポーネントのデザイン実装(既存 CSS の踏襲) |
| **担当者(発注側窓口 兼 実装管理)** | 各種サービスの設定・契約、認証情報の管理、コードレビュー、動作確認、本番切替判断、委員会との折衝 |

**方針: 人間の稼働を最小化する。** Claude が実行可能な作業はすべて Claude に寄せ、
人間は「Claude が原理的に実行できない作業」と「判断・承認」に専念する。

## 2. Claude が実行できない作業(= 人間の必須タスク)

以下は必ず担当者が手を動かす必要がある。**これがボトルネックになるため、着手を前倒しすること。**

### 2-1. アカウント・契約系
- [ ] microCMS アカウント開設、サービス作成
- [ ] microCMS の編集者アカウント 3 つの発行・パスワード設定
- [ ] Instagram アカウントのビジネス/クリエイター切替(未対応の場合)
- [ ] Instagram フィード埋め込みサービスの登録(採用する場合)

### 2-2. 管理コンソール操作系
- [ ] Cloudflare Pages のビルド設定変更(Astro ビルドコマンド・出力先の指定)
- [ ] Cloudflare のプレビュー環境(develop ブランチ)有効化
- [ ] Cloudflare のデプロイフック URL 発行
- [ ] microCMS 側の Webhook 登録(発行したデプロイフック URL を設定)
- [ ] microCMS の API スキーマ登録(Claude が設計書を出力 → 画面上で入力)
- [ ] 環境変数(microCMS の API キー等)の Cloudflare への登録

### 2-3. 判断・確認系
- [ ] プレビュー URL での目視確認(PC / スマホ実機)
- [ ] 現行本番との表示差異の判定
- [ ] 本番切替の GO / NO-GO 判断
- [ ] 委員会への報告・承認取得

### 2-4. 素材系
- [ ] アーカイブ用の過去大会の画像・紹介文の準備
- [ ] 協賛一覧の最新情報の確認

## 4. 週次の進行フロー(定型)

```
1. 担当者が Claude に「次のフェーズを進めて」と指示
2. Claude が develop ブランチで実装 → push → PR 作成
3. Cloudflare が自動でプレビュー URL を生成
4. 担当者がプレビュー URL で確認
5. 問題あれば Claude に修正指示(このサイクルを繰り返す)
6. OK なら PR をマージ
```

**担当者が Git コマンドを打つ必要はない。** PR のマージはブラウザ上で完結する。

## 5. 週別タスク割当

### 第 1 週: 基盤構築
| 担当 | タスク |
|---|---|
| 人間 | microCMS 開設 / Cloudflare ビルド設定 / develop ブランチのプレビュー有効化 |

### 第 2 週: CMS 連携
| 担当 | タスク |

| Claude | スキーマ設計書の出力、既存 67 箇所の data-field を CMS 取得に置換、data.json 廃止、初期データ投入用データの整形 |
| 確認 | 管理画面の値を変えるとプレビューに反映されるか |

### 第 3 週: 新機能
| 担当 | タスク |
|---|---|
| 人間 | Instagram のアカウント設定・埋め込みコード取得 / アーカイブ用素材の投入 / Webhook 登録 |

| 確認 | アーカイブページのデザイン・自動生成、Instagram の表示 |

### 第 4 週: 検証・移行
| 担当 | タスク |
|---|---|
| 人間 | 全ページの受入確認、実機テスト、本番切替の実行判断、委員会報告 |
| Claude | 表示差異の修正、URL 一覧の突合、GA4 組み込み、運用手順書の作成、切替前タグ付け |
| 確認 | 本番反映後の最終確認 |

## 7. リスク管理(内部)

| リスク | 兆候 | 対応 |
|---|---|---|
| 人間側の設定作業が遅れ全体が止まる | 週次の設定タスクが未着手 | **最大のリスク。** 第 1 週のアカウント開設・Cloudflare 設定を最優先で完了させる |
| microCMS 無料枠の制限に抵触 | API 5 個超過 / 転送量 20GB 超過 | API は 4 個設計で 1 枠余裕を確保済み。画像は Cloudflare 側に配置し転送量を抑制 |
| Astro 化で既存アニメーションが崩れる | Vivus / Slick / inview の不具合 | 第 1 週に集中的に検証。崩れる場合は該当ページのみ従来方式を残す退避策 |
| 1 ヶ月の納期に対しレビュー往復が増える | 修正指示が週 3 往復以上 | 確認観点を事前に絞る(表示崩れ・文言・リンクの 3 点に限定) |
| 本番切替の失敗 | 切替後に表示異常 | 切替前に現行構成へタグを打ち、即ロールバック可能にしておく |
