# WordPress 移行計画書

作成日: 2026-07-24
対象サイト: KADOMA ART FES 公式サイト (https://kadoma-artfes.jp/)
現行構成: 静的 HTML + jQuery + data.json(ヘテムル / FTP 運用)

---

## 1. 移行の目的

| 現状の課題 | WordPress 移行で得られる解決 |
|---|---|
| 更新のたびに HTML 編集 + FTP アップロードが必要 | 管理画面からブラウザだけで更新完了 |
| 更新作業が特定の担当者に依存(属人化) | 複数人での分担・権限管理(編集者/投稿者)が可能 |
| news 更新は data.json の手編集 | 「お知らせ」を投稿として管理、過去分も自動アーカイブ |
| 年度切替は data.json + 画像差し替え | カスタムフィールドで管理画面から年度情報を一括更新 |
| ギャラリーページが年度ごとに手作業で複製 | 投稿タイプ + メディアライブラリで自動生成 |
| アクセス解析なし | GA4 プラグイン等の導入が容易 |

### 現行リファクタリング資産との関係

フェーズ 1〜3 で実施した「年度依存値の洗い出しと data.json への集約」は、WordPress 移行の **要件定義そのもの** として活用できる。data.json の構造(edition / event / contest / marche / images / gallery / contact / organization / social / news)は、そのままカスタムフィールド設計・投稿タイプ設計の設計図になる。

### 共通パーツ(includeHTML/)

| パーツ | WordPress での対応 |
|---|---|
| header.html | `header.php`(テーマテンプレート) |
| menubar.html | ナビメニュー(`wp_nav_menu`、管理画面から編集可) |
| hbpinfo.html | ウィジェット or 再利用ブロック |
| footer.html | `footer.php` |

### 年度依存データ(data.json)

edition / event / contest / marche / images / gallery / contact / organization / social の各セクション → **サイト全体設定(オプションページ)のカスタムフィールド群**に移行。news 配列 → **通常の投稿**に移行。

### アセット

- 画像: `images/`, `images_gallery/`, `images/gallery/` → メディアライブラリへ取り込み
- PDF: `KAF5entry.pdf` など → メディアライブラリ
- CSS: `style.css`, `sub-page.css`, `inview.css` → テーマの CSS として移植
- JS: `main.js`, `slick.js` ほか → テーマの JS として移植(include.js / data-loader.js は **不要になり廃止**)

## 3. 方針の選択肢

### 3-A. ホスティング

| 案 | 内容 | 評価 |
|---|---|---|
| A1 | 現行ヘテムルに WordPress をインストール | ◎ 追加費用なし。ヘテムルは WordPress 簡単インストール対応。ドメイン移設不要 |
| A2 | WordPress 専用ホスティングへ移設 | △ 性能は上がるが費用・移設作業が増える |

**推奨: A1**(ヘテムルのまま)。

### 3-B. テーマ戦略

| 案 | 内容 | 評価 |
|---|---|---|
| B1 | 現行デザインを再現するオリジナルテーマを自作 | ◎ 見た目を完全維持。現行 CSS/JS を流用。制作コストは中 |
| B2 | 既製テーマ + カスタマイズ | △ 早いが現行デザインから変わる。CSS 移植の手間は結局発生 |
| B3 | ブロックテーマ(FSE)でゼロから | △ 将来性はあるが学習コスト大、jQuery アニメーションとの相性調整が必要 |

**推奨: B1**(クラシックテーマ自作)。現行の HTML/CSS/JS 資産をほぼそのまま `header.php` / `footer.php` / `front-page.php` / `page-*.php` に分解して移植する。デザイン変更を伴わないため利用者への影響ゼロ。

### 3-C. 年度データの持たせ方

| 案 | 内容 | 評価 |
|---|---|---|
| C1 | オプションページ(全体設定)にカスタムフィールド | ◎ data.json と同じ「1 箇所更新」思想。Smart Custom Fields / SCF や ACF 無料版で実現可 |
| C2 | 「大会」カスタム投稿タイプ(KAF5, KAF6, …を投稿として管理) | ○ 過去大会のアーカイブ化に強い。設計はやや複雑 |

**推奨: C1 を基本に、ギャラリー・受賞作品のみ C2 的な投稿タイプで管理**するハイブリッド。

## 5. リスクと対策

| リスク | 対策 |
|---|---|
| ヘテムルの PHP/MySQL バージョンが古い | W0 で最初に確認。不足なら契約プラン変更を検討 |
| 移行中に本番サイトが崩れる | テスト環境(サブディレクトリ/サブドメイン)で完成させてから切替。現行静的サイトはそのまま残るので即座に戻せる |
| URL 変更による SEO 低下 | 301 リダイレクト + Search Console 再送信 |
| jQuery プラグイン(Slick 等)と WordPress 同梱 jQuery の競合 | `wp_enqueue_script` で読み込み順を制御。noConflict 対応確認 |
| WordPress のセキュリティリスク(静的サイトには無かった) | 自動更新有効化、ログイン保護プラグイン、定期バックアップ |
| コンテスト応募期間のアクセス集中 | キャッシュプラグイン導入。静的キャッシュならヘテムルでも十分捌ける |

## 6. GA4 との関係

GA4 は WordPress 移行後に導入するのが効率的(テーマの `header.php` 1 箇所への追加、または Site Kit プラグインで完結)。移行前の現行サイトに実装しても、移行時に作業がやり直しになるため、**GA4 は移行フェーズ W6 に組み込む**。

コンテスト応募ページの離脱率計測(当初の目的)は、WordPress 化後:
- Site Kit または手動 gtag でページ別エンゲージメント率を取得
- 応募フォームボタンクリックをイベント計測
- スクロール深度で離脱ポイントを特定
